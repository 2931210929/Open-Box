## 终端分流专项

- 初始只读诊断确认：单个 IPv4 规则能正确选择终端出站，同一设备的 IPv6 连接因来源地址族不匹配而落到目标策略。修复仅在当前 DHCP/邻居证据能唯一确认 MAC 时生成 IPv6 补充规则；补充条件是 IPv6 来源与 MAC 的交集，不扩大到同 MAC 的其他 IPv4，也不推断网段身份。
- 开发路由器真实 LAN 网桥上的临时终端验证 IPv4、固定 IPv6、临时 IPv6：百度和 YouTube 均命中指定终端出站，完成 TLS。另一 MAC、同 MAC 的其他 IPv4 仍走目标策略；热更新保留部署时确认的身份。
- 复现并修复 #683：按 MAC 分流时，防火墙劫持的 DNS 快速路径缺少来源 MAC。查询先转入可识别邻居身份的 DNS 入站后，auto_redirect 与纯 TUN 下的 IPv4/IPv6、路由器 DNS 和外部 TCP DNS 均命中终端 FakeIP 规则，业务连接使用指定出站。
- 双栈与 DNS 专项共 33 项断言、20 次探测通过。全局 IPv6 关闭、交给节点、代理降为 IPv4、不进内核均按统一设置运行；关闭时有实际防火墙拒绝，降级时 AAAA 回空并拒绝裸代理 IPv6，不进内核时有系统 WAN 路由、连接跟踪及成功 TLS 的证据。终端直连、拒绝也完成实流量验证。
- 全局 IPv6 的系统转发测试使用开发机专用临时 ULA/SNAT 提供出口可达性。临时命名空间、接口、IPv6 地址、来源路由和 nft 表均已清理。拒绝用例按实际 `route(拒绝)`/`outbound/block` 行为修正断言后单独重跑通过，原始失败断言与日志保留。
